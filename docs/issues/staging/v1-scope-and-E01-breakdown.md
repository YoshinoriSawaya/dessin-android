# 下書き: v1の範囲とE01のタスク分解

`docs/web-reference.html` を読んで作った案。利用者が確認・修正したあとに、epics/tasks へ移す。

## v1の範囲(案)

方針: Web版でできることをそのまま移す。新機能は入れない。

### 入れる
- 部位20個(肋骨・首・頭・骨盤、左右の肩・上腕・前腕・手・付け根・もも・すね・足)と、親から子への配置順
- 部位の選択(チップ・3D上のタップ)、外す(子孫ごと)、向きを戻す
- 玉のドラッグ(可動域内にクランプ)、緑領域のダブルタップで向きを決める
- 回転オーブ(中央のドラッグで傾け、外周のドラッグでひねる。スイング・ツイスト分解でクランプ)
- スライダー
  - 肋骨: 大きさ・前後の傾き・ひねり・横の傾き
  - 各部位: ひねり
  - 頭の大きさ、肩幅、骨盤の横幅、付け根の内寄り
- 肋骨のドラッグ移動
- カメラ: 1本指の回転、ピンチでのズーム、正面・横・背面・上、全体を表示
- 表示の切替: ガイド、正中線、関節の玉、格子
- 影、床、格子(見た目は簡略化してよい)

### 入れない(v1以降の候補)
- ポーズの保存・読み込み、Undo
- 画像の書き出し(端末のスクリーンショットで代用)
- 部位同士の当たり判定(Web版にもない)
- 左右対称のコピー、プリセットのポーズ

### 利用者に決めてほしいこと
1. 上の「入れない」で問題ないか。特にポーズの保存は要らないか
2. CLAUDE.md の「当たり判定」は、Web版にない部位同士の衝突を指すのか、タップのレイキャスト(ピッキング)を指すのか
3. 対応OSの下限(minSdk)と、OpenGL ES のバージョン(3.0を想定)
4. 画面の向き(縦固定でよいか)

## E01 ロジック層の移植: タスク分解(案)

すべて純Kotlin・JVMテスト・テスト先行。三角関数の誤差の許容は 1e-6 を目安にする。

| ID | 内容 | 主なテスト |
|----|------|-----------|
| E01-01 | 最小限の数学型(Vec3、Quat、Ray) | 正規化、積、逆元、`setFromUnitVectors`・`setFromAxisAngle` 相当、ベクトルの回転 |
| E01-02 | 部位の定義データ(寸法・取り付け位置・a0・ref・コーン・ロール・ヒンジ)と左右の鏡像化 | 右側は ±x のコーンを入れ替え、ロールを反転。20部位と親子関係 |
| E01-03 | 基準フレーム Qb と方向 `dirVec(φ,ψ)`、可動域 `phiMax(ψ)` | 4象限の楕円境界、ヒンジは max を返す、上限は π |
| E01-04 | 状態→姿勢(`applyState`: Qb·swing·roll·Qb⁻¹)と、玉の位置 | 休止状態で単位回転になる。既知の φ・ψ・roll で期待する方向になる |
| E01-05 | 方向→状態(`aimPart`)。コーンとヒンジでクランプ | 範囲外の方向が境界に収まる。φ≈0 のとき ψ を保つ。ヒンジの min・max |
| E01-06 | ドラッグ入力(レイと球の交点、2つの交点のうち近いほう、外れたら最近点) | 交点の選び方、レイが外れたとき |
| E01-07 | 回転オーブ(スイング・ツイスト分解、roll を [−π,π) に折り返してクランプ) | 純粋なツイストやスイングの分解、範囲外の roll のクランプ |
| E01-08 | 骨格の状態管理(配置済み・配置可能、外すと子孫も外れる、ワールド変換の合成、肋骨の位置・回転・拡大) | 親を回すと子のワールド位置が追従する。外すときの連鎖 |
| E01-09 | 調整パラメータ(肩幅→上腕の取り付け位置、骨盤の幅と内寄り→付け根の長さともも位置、頭の大きさ) | `updateHips` の式(下限 0.03)の再現 |
| E01-10 | Web版との照合用テストベクタ | 同じ入力で Web版と同じ姿勢になる(E01の完了条件) |

依存: 01 → 02・03 → 04 → 05・06・07・09 → 08 → 10。05・06・07・09 は並行できる。

### 補足
- E01-10 のテストベクタは、ブラウザの開発者ツールで Web版にログを仕込んで取る想定。取り方は E01-10 の着手時に決める
- カメラ(軌道・`fitView`)の計算と、ピッキングのためのレイ生成は、純Kotlinに置けるが UI寄り。E01に入れるか、描画エピックに回すかは要判断(案: 描画エピック)
- ダブルタップの判定(420ms以内、32px以内)は UI層に置く
