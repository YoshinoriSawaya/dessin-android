# E13-04 場面の保存

親: [E13](../epics/E13-multi-doll.md)

## 概要
- 複数の人形をまとめて保存・読み込みできるようにする
- 今のポーズの保存(1体)との関係を決める

## 決まったこと
- 保存は場面としてまとめて(全員の位置・ポーズ・体型)。今までの1体のポーズは、読み込むと操作中の人形に入る(2026-11-14、利用者)
- 場面の名前の候補は「場面 N」。画面の「保存したポーズ」は「保存した場面」にした(Claude が決めた)
- 根はポーズと同じく保存しない(Claude が決めた)

## 進め方
保存形式(`:core`)はテスト先行。画面は手動確認

## 完了条件
- 保存形式のテストが通る(古い1体のデータも読める)
- 実機で場面を保存・読み込みできる

## 依存
E13-01

## 設計の決定
- `SceneCodec`: 場面の見出しのあと、人形ごとに `doll`・`bodytype <体型>`・ポーズ(PoseCodec)を並べる。11体目からは読まない。形の誤りや人形が無い場面は読めない
- `SceneLibrary`: 保存は場面(kind が scene)。保存の一覧の仕組み(`NamedLibrary`)に、ほかの種類のファイルの読み方(otherKinds)を足し、今までのポーズのファイル(kind が pose)も `SavedItem.Pose` として読む。置き場所はポーズと同じ files/poses
- `loadScene`: 全員を差し替え(体型も場面のもの)、最初の人形を操作中にし、全体を表示し直す。今までのポーズは `loadPose`(操作中の人形に入り、体型は今のまま)
- 画面の状態(アプリを閉じても残す)には E13-01 で全員を残している

## 検証結果
- テスト先行: `SceneTest`(文字列で戻す・壊れた場面・保存と読み込みと名前の候補・今までのポーズのファイル・読み込みで全員を差し替え)を書き、未定義でコンパイルが通らないことを確認してから実装した。途中で失敗した2件は、テストの準備で身長を首を選んだまま変えていた(身長のスライダーは胸を選んでいるときに出る)ためで、準備の順番を直した。既存のテストは変えていない
- `./gradlew lint test assembleDebug` → BUILD SUCCESSFUL(テスト391件、うち照合3件は停止、失敗0件。lint は既存の警告5件)
- エミュレータ(AssetDash_API37、`--es demo multi`): 3体の場面を「場面 1」で保存 → アプリを止めて起動し直す(1体の初めの状態)→「保存した場面」に「場面 1」と v1 の「ポーズ 1」が並ぶ →「場面 1」を読み込むと3体が戻り、最初の人形が操作中。クラッシュなし
