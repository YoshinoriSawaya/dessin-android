# E02-05 ピッキング

親: [E02](../epics/E02-render-ui.md)

## 概要
- レイと三角形の当たり判定で、表示中の部位・選択中の玉・選択中の可動域のどれに当たるかを求める(Web版の pickPart・romPoint)
- 玉が他の部位より優先されること、可動域に当たったときは親の部位を選ばないこと(Web版の pointerdown の規則)

## 進め方
`:core`(テスト先行)

## 完了条件
- 当たる・当たらない・優先順位をJVMテストで確かめる

## 依存
E02-02

## 設計の決定
- `:core` の `pick` パッケージに置いた。`pickPart`(Web版の pickPart)・`romPoint`(romPoint)・`pickDot`(玉)・`pickAtPress`(pointerdown の「緑の範囲に当たったら親は選ばない」規則まで含めた判定)
- 当たり判定は three.js r128 と同じ: 三角形ごとの交点(Ray.intersectTriangle と同じ式)、片面の材質は表側だけ(顔の面と可動域は両面)、当たった中で最も手前。選択中の部位の玉に当たれば、手前に何があってもその部位
- 当たる対象は描いているもの(`drawPlan`)と同じ。ゴーストも選べ、関節の玉を消していれば玉では選べない
- 玉は可動域の表示の中にあるので親の向きに回して置き、大きさは視点(レイの始点)からの距離で決める(Web版の updateGuide)
- 照合データの操作の再生を、テスト用の補助 `GoldenState` にまとめ、E01-10 の `WebGoldenTest` もこれを使うようにした(照合の中身は変えていない)

## 検証結果
- テスト先行: `PickingTest`・`PickGoldenTest` を書き、コンパイルエラーで失敗することを確認してから実装した
- Web版との照合: `tools/golden/generate.mjs` にピッキングのデータの生成を足した。視点6通り×いくつかの姿勢と選択で、1440回のレイの「押した部位」「緑の範囲の点」「押した先」がすべて一致(玉に当たる場面、緑の範囲に当たる場面、親を選ばない規則が効く場面6件を含む)
- 途中で直したこと:
  - 照合データに「親を選ばない」場面が少なかった(1件)ので、関節の近くと親の形を狙うレイを増やした(テストの条件は下げていない)
  - 単体テストで手で決めたレイが想定外の部位(ゴーストの頭、胴)に当たっていたので、レイを決め直した。親を選ばない規則の単体テストは、照合データの1件を使った
- `./gradlew lint test assembleDebug` → BUILD SUCCESSFUL(テスト192件成功、lint は 0 errors、既存の警告5件のみ)

## 未検証のまま残したこと
- 指でのタップとの組み合わせ(画面の座標からレイを作ってこの判定を呼ぶ)は E02-07 で確かめる
- 当たり判定は全メッシュの三角形を毎回ワールドに移して調べる。全部位を置いても1回あたり数千三角形なので問題ない見込みだが、実機での速さは E02-07 で確かめる
