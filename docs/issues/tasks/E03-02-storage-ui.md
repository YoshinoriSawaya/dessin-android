# E03-02 保存先と保存・読み込みのUI

親: [E03](../epics/E03-pose-save.md)

## 概要
端末内に保存し、UIから保存・読み込みする。

## 完了条件
- 実機で保存し、アプリを再起動して読み込める

## 依存
E03-01, E02

## 設計の決定
- 保存の形は「名前を付けて複数」(2026-11-11、利用者の判断)
- 一覧・保存・読み込み・削除の規則を `:core` の `PoseLibrary` に置いた(テスト先行)。置き場所は `PoseStore` で差し替えられ、テストではメモリ上の置き場所を使う
  - 1件のファイル: `dessin-saved 1` / `name <名前>` / `saved <ミリ秒>` / `pose` / PoseCodec の文字列
  - 名前は前後の空白を取り、改行は空白にし、40文字まで。空なら「ポーズ N」(保存済みの「ポーズ 数字」の最大 + 1)
  - 一覧は新しい順。壊れたファイルは一覧から外し、id をログに残す
  - 失敗(読み書きの IOException、形式の誤り)は `LibraryResult.Error` で返す。画面は理由をログに残し、利用者には短い文言をトーストで出す
- 保存するのはポーズ(骨格・肋骨の置き方・体型)だけで、視点や選択中の部位は含めない。読み込むと、選択中の部位が置かれていなければ肋骨を選び、全体を表示する(`EditorState.loadPose`)
- 置き場所はアプリ専用のフォルダの `files/poses/<id>.pose`(`FilePoseStore`)。id は UUID で、英数字とハイフン以外は弾く(フォルダの外を指さないように)。書き込みは一時ファイルに書いてから名前を変える
- UI: 操作パネルに「保存」の段を足し、「名前を付けて保存」(名前の欄には候補を入れておく)と「保存したポーズ」(一覧から読み込む・削除。削除は確認してから)を置いた
- v1 では上書き保存と名前の変更は入れない(同じ名前で保存すると別の1件になる)
- ファイルは小さいので、読み書きは UI のスレッドで行う

## 検証結果
- テスト先行: `PoseLibraryTest`(10件)と `LoadPoseTest`(2件)を書き、コンパイルエラーで失敗することを確認してから実装した
- `./gradlew lint test assembleDebug` → BUILD SUCCESSFUL(テスト254件成功、lint は 0 errors、既存の警告5件のみ)
- エミュレータ(AssetDash_API37、Android 17)で adb の input で操作して確認(Claude):
  - 全部位を置いた姿勢で「名前を付けて保存」→ 名前の欄に「ポーズ 1」→ 保存 →「「ポーズ 1」を保存しました」と出て、`files/poses/` に1件できる
  - アプリを止めて起動し直す(初期状態に戻る)→「保存したポーズ」に「ポーズ 1」と保存日時が出る →「読み込む」で保存した姿勢に戻り、全体を表示される
  - 「削除」で確認が出て、削除すると一覧が「保存したポーズはありません」になり、ファイルも消える

## 未検証のまま残したこと
- 実機での確認(完了条件は実機だが、エミュレータで同じ手順を確かめた)
- 日本語の名前の入力(adb の input は英数字しか打てないので、候補の名前のまま保存した)
- 書き込みや読み込みに失敗したときの文言は、手で失敗を起こして確かめていない(単体テストでは失敗を起こして Error になることを確かめた)

## あとから直したこと
- ダイアログなどの色を Web版の配色に揃えた(アプリ全体のテーマ `DessinTheme`。背景はパネルの色、主な操作はアクセント、キャンセル・閉じるは墨、一覧の削除は淡い色)。エミュレータで保存・一覧・削除の確認の3つのダイアログを確認
