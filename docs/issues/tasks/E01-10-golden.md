# E01-10 Web版との照合

親: [E01](../epics/E01-logic-port.md)

## 概要
Web版を Node で動かしてテストデータを作り、同じ操作で Kotlin のロジック層が同じ姿勢になることを確かめる。

## 完了条件
- テストデータでのJVMテストが通る(E01の完了条件)

## 依存
E01-08

## 設計の決定
- 当初の案(ブラウザでログを取る)をやめ、`tools/golden/generate.mjs` で自動生成にした(利用者が了承)
  - `docs/web-reference.html` のインラインスクリプトを、jsdom 上で three.js r128 と一緒に実行する。描画(WebGL・2Dキャンバス)は何もしない部品に差し替える
  - 参照実装への書き足しは2か所だけ: 内部関数を外から呼ぶための `window.__dessin`、レイを外から与えるための `setRay` の先頭。書き足す位置が見つからなければ生成を止める
- データは操作の列と、各操作のあとの全20関節(ワールドの位置・回転・拡大率、状態 φ・ψ・roll、玉のワールド位置)。テキスト形式で `core/src/test/resources/golden/web-golden.txt` に置く(JSONの依存を増やさないため)
- 場面は手で決めた4つと、乱数(種を固定)の6つ。操作は配置・外す・向きを戻す・状態の直接指定・方向へ向ける・点へ向ける・ドラッグ・回転オーブ(部位と肋骨)・肋骨の置き方・体型の調整
- 許容誤差は 1e-6

## 検証結果
- 初回は1件ずれた。生成スクリプトが長さ1でない方向を Web版の `aimPart` に渡していたため。Web版の `aimPart` は単位ベクトルが前提で、実際の呼び出し元(`dragPart`・`aimAtPoint`)は正規化して渡すので、生成側で正規化するように直した(Kotlin 側とテストの許容誤差は変えていない)
- `npm run generate` → 10場面・297操作(配置79、回転オーブ44、ドラッグ34、方向へ向ける32、向きを戻す24、肋骨の置き方20、体型19、状態の直接指定17、外す16、点へ向ける12)
- `./gradlew :core:test` → `WebGoldenTest` を含め、全111件が成功。全操作のあとの全関節が 1e-6 以内で一致
- `./gradlew lint test assembleDebug` → BUILD SUCCESSFUL(lint は 0 errors、既存の警告5件のみ)

## 未検証のまま残したこと
- 照合しているのはロジック層だけ。画面座標からレイを作る部分、カメラ、描画は E02 で確かめる
- Web版で three.js のオブジェクトを経由する計算(行列の分解など)とは、浮動小数点の誤差の範囲で一致している。1e-6 より厳しい一致は求めていない
