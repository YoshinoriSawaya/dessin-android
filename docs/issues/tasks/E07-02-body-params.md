# E07-02 体型のデータと調整

親: [E07](../epics/E07-body-type.md)

## 概要
- 体型を表すデータを作り、画面から調整できるようにする
- 項目に入るもの(2026-11-14、利用者): 首の長さ、頭の大きさ(E07-01 の 70% を基準にする)
- v1 にはすでに体型の調整パラメータ(頭の大きさ・肩幅・骨盤の横幅・付け根の内寄り、スライダーで調整)がある。これを土台にして項目を足す

## 決まったこと(2026-11-14、利用者)
- 項目: 頭の大きさ・肩幅・骨盤の横幅・付け根の内寄り(v1 からある)に、首の長さ、首の付け根の位置(前後だけ)、上腕・前腕・もも・すねの長さ(それぞれ別、左右共通)、身長、ひざの転がりのずれを加える
- 身長は体型に足し、胸の「大きさ」(ポーズ側)も残す。人形の大きさ = 身長 × 胸の大きさ
- ひざの転がりのずれは体型の項目にする(E10-02 をここへ移した)
- 調整は今のまま部位ごとのスライダーに出す(頭を選ぶと頭の大きさ、首を選ぶと首の長さ、など)

## 進め方
体型から骨格への反映は `:core` でテスト先行。画面は手動確認

## 完了条件
- 体型を変えたとき骨格・玉の位置が正しく追従するテストが通る
- 実機で調整できる

## 依存
E07-01

## 設計の決定
- `BodyParams` に8項目を足した(既定の値は v1 と同じ姿)。範囲: 首の長さ 50〜200%、付け根の前後 −70〜20mm(既定 −35)、手足の長さ 70〜130%、身長 70〜130%、ひざの転がり 0〜60mm(既定 30)
- 長さの倍率(`lengthScale`)は部位の形を縦に伸ばし、子の取り付け位置と可動域の表示(緑の範囲・玉)の半径もそれに従う(`Skeleton.guideScale`)。関節の玉の大きさは変えない
- 身長は根(胸)の拡大率に掛ける。ひざの回転の中心のずれは `pivotOf` で体型から取る
- スライダー: 胸に「身長」、首に「長さ」「付け根の前後」、上腕・前腕・ももに「長さ(左右)」、すねに「長さ(左右)」「ひざの転がり」
- 体型を文字列にする `BodyCodec`(「名前=値」を並べた1行。知らない名前は読み飛ばし、無い項目は既定の値、値は範囲に収める)を作った。画面の状態(`EditorStateCodec`)に `bodytype` の行として入れ、アプリを作り直しても体型を失わない
- ポーズの保存形式(`PoseCodec`)は変えていない。保存したポーズには v1 の4項目だけが入る(体型をポーズから外すのは E07-03)

## 検証結果
- テスト先行: `BodyTypeTest`(骨格・形・可動域の表示)、`BodyCodecTest`、`SlidersTest`・`EditorStateCodecTest` への追加を書き、未定義でコンパイルが通らないことを確認してから実装した
- 既存のテスト3か所を変えた。理由: 胸と首にスライダーが増える仕様の変更のため
  - `SlidersTest.肋骨は大きさと3つの傾き`: 末尾に身長を足した
  - `SlidersTest.肋骨の値はオイラー角を度に丸めて出す`: 値の並びの末尾に身長(100)を足した
  - `SlidersTest.部位はひねり_範囲が0なら使えない`: 首のスライダーの一覧ではなく先頭のひねりだけを比べるようにした
- `./gradlew lint test assembleDebug` → BUILD SUCCESSFUL(テスト295件、うち照合3件は停止、失敗0件。lint は既存の警告5件)
- エミュレータ(AssetDash_API37): 胸に身長、首に長さと付け根の前後、上腕に長さ(左右)が出る。上腕の長さを 127% にすると両腕が伸び、前腕・手が先についていき、緑の範囲と玉も広がる。首の長さを 190% にすると首が伸びて頭がついていく。クラッシュなし

## 未検証のまま残したこと
- 実機での操作感
- 首の可動域の表示は、もともと首の長さより大きな半径(0.2)なので、首を長くすると大きく広がって見える
- 身長を変えると足が床からずれる(胸の大きさを変えたときと同じ。v1 からの振る舞い)
- エミュレータでは、すねの長さ・ひざの転がり・付け根の前後・身長のスライダーを画面で動かしていない(テストで確かめた)
- 保存したポーズには新しい項目が入らない(E07-03 で扱う)
